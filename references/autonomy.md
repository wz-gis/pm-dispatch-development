# Autonomy And Recovery

只在处理不确定性、恢复失败或 Blocker 时加载本文件。

## 默认动作

- 可逆、局部且能验证的选择直接执行，并在证据中记录假设。
- 只有同时满足“本地无法发现”“不同选择会实质改变结果”“选错代价高或不可逆”时才向用户澄清。
- Warning 不阻止实现；Validator Error 只阻止它对应的分发、Gate 或收口动作。

## 同一 Worker 恢复

首次命令、构建、测试或工具失败不是 Blocker，也不创建新 Attempt。当前 Worker 最多做一次同方法重试、两种实质不同的替代恢复路径和一次聚焦复验。实现方式、文件布局、测试命令和局部修复可在同一 Attempt 内调整。

只有以下变化创建新 Attempt：

- 凭据、权限、数据破坏、发布或其它安全边界变化；
- `design_freeze` 中范围、用户可见契约、安全约束或验收标准变化并产生新指纹。

Worker 断线先在原 Attempt 内做状态探测和一次宽限复查。只有 Lease 已过期且 Worker 身份确认不可恢复时，才视为 Lease 所有权安全边界变化：过期旧 Attempt、释放锁，并从最后 Artifact/进度创建替代 Attempt。单次等待超时不创建 Attempt，也不标记 Blocked。

## 硬 Blocker

仅以下情况可令 Task 进入 Blocked：凭据/2FA/CAPTCHA；不可逆外部操作缺少人工授权；受保护契约存在高代价歧义；真实依赖或资源锁冲突；外部系统不可用且已尝试两条不同恢复路径；恢复预算耗尽。记录 `hard`、`cause`、`recovery_attempts` 和唯一 `next_unblock_action`。

## 风险化复验

- 局部改动：聚焦测试和 diff 检查。
- 共享行为：相关回归集。
- 跨系统：集成证据。
- 生产或不可逆路径：运行态、回滚和用户路径证据。

只收集足以满足当前 Gate 的证据，不重复读取或重复执行已通过且未受影响的检查。
